# PromptCraft v0.4.0 — 诚实性闭环：把「失败了但界面说成功」全部关掉

> **本版本不宣称任何效果数字。** 原因写在下面第 3 节，说得很具体。

---

## 1. 这个版本做了什么

一轮以「**把失败显示成成功**」为唯一主题的清理。起点是一份判定 **FAIL** 的架构审查
（26 项建议、13 条发布阻断级），终点是 **41 条同族缺陷全部闭环**，由一条命令逐条复核：

```
$ python scripts/check-fail-open.py
OPEN 0 / FIXED 41 / UNVERIFIED 0 / TOTAL 41
✅ 全部 P0 已闭环，且无未判定项。
```

### 1.1 三个发布阻断项（v0.3.5 已发布版就带着它们）

**① API Key 存不进去。** v0.3.5 给 `ProviderConfig.api_key` 加了 `skip_deserializing`
以防凭据投毒，但「保存凭据」与「保存配置」共用同一个反序列化入口 ⇒ `set_password`
**永不被调用** ⇒ 新装用户填完 Key 点保存，界面报「配置已保存」，后端静默丢弃。
**这一版彻底修好**：凭据与配置拆成两条独立的路，配置保存路径**再也没有写凭据的能力**
（纵深防御测试钉住）。

**② 导入包可以把你的真实 API Key 外发给攻击者。** v0.3.5 只防住了「Key 的**值**」
被投毒，没防住「Key 的**目的地**」被投毒——导入包能改写 `base_url`，真实 Key 就作为
Bearer 头发往那个地址。现三重防护：校验下沉到存储层、**导入包一律不得改写端点**
（单靠 scheme 校验挡不住，攻击者地址同样是 https）、读路径修复已中招的机器。

**③ 导出静默截断 500 条**，界面却报「已导出 N 条」。现已走无 LIMIT 的完整查询。

### 1.2 「错了但界面说成功了」

结构解析彻底失败时，界面曾斩钉截铁地说「**增强器判断无需修改，建议直接使用原文**」——
**断言了一个从未发生的判断**。现在：

- 降级路径携带**自己的失败原因**（新字段 `failure_reason`），不再借用「模型判断」字段；
- `enhancement_level` / `delivery_status` 改为可选：缺失就是缺失，前端按
  **不可判定**呈现，绝不补默认值；
- 呈现逻辑收敛到唯一的真值解析器，逐字段的「真实含义 / 允许文案 / 禁止文案 / 触发条件 /
  依据」见随包的 `UI真值清单.md`。

同时修掉的四条「界面在替系统说没做过的事」：

| | 原来 | 现在 |
|---|---|---|
| 连接验证 | Key 留空时**一次请求都没发**，仍显示「连接验证成功」 | 验证与保存分别陈述；未验证时明说「未验证连接」 |
| 计费口径 | 导入包能静默改写价格 ⇒ 月度强制额度形同虚设 | 沿用本机价格，并如实报告「未采用」 |
| 失败处理 | 失败时**丢掉上一条已付费的结果** | 保留并标注「这是上一次的结果（时间）」 |
| 结果相同 | 结果与原文逐字相同，仍显示「轻度增强」 | 改为事实陈述「这一版与你的原文完全相同」 |

### 1.3 测量系统自己的诚实性

这一轮最深的问题不在产品，在**测量系统**：

- **人工盲评的揭盲映射有一个大小写反转 bug**（`"a" == "A"` 恒为 False），
  27 条人工判断被全部记成「原文更优」。修正后为 10/17/21，方向一致（弱）。
  **只影响「谁胜」的分类**，四维 Delta 与自动裁判列不受影响。
- 缺数据一律 fail-closed：不再把缺失写成 0/默认值；裁判失败样本显式计入分母；
  未测量的维度不出现在相关性表里；**未定义的相关性返回「不可判定」而不是 ρ=0**。
- 评测产物**必须编码自身身份**（提示词版本 + 正文哈希 + 模型 + 温度 + 样本集哈希 +
  重复次数），续跑前做身份一致性闸——**改完提示词再续跑不再会把新旧混进一份产物**。
- 评测脚本与原始数据进版本控制，档位稳定性的原始响应已重跑再生并归档（含 sha256）。

## 3. 为什么这个版本不宣称效果数字

原规格里作为主线的三条门槛——clear 翻转率 ≤30%、medium ≤30%、clear light 出现率 ≥42%——
经**可判定性推导**（`Var = p(1-p)/n + τ²/R`，τ = 41 点噪声地板）**全部落在不可判定区**：

- clear 翻转率这一条要变得可判定，需要 347 条样本 × **50 轮**（≈ 17,350 次调用，约 $38、数小时）；
- medium 的间距只有 3 点，所需轮次是 3000。

**实测证据**：同一份样本、同一模型、同一提示词，**两次独立运行**的 clear 一致率是
45% vs 55%、medium 70% vs 90%——差异全部落在 41 点噪声地板以内。
也就是说，**一个被当作发布门槛的数字，两次独立运行就差 10~22 点，与门槛间距 25 点同量级**
⇒ 该门槛重跑约等于掷骰子。

⇒ **这三条门槛已正式作废**（作废 ≠ 通过：它们仍会显式出现在门禁输出里，只是不参与放行）。
**档位稳定性推迟**，留待「把档位决策从 LLM 手里拿走」（规则化 / 前置分类器 / 让用户在两个
结果里选）有新方案之后再测。

⇒ **在有可判定的验收物之前，不发布效果数字。** 这一版唯一的效果线是**澄清质量**
（严重模糊与 severe 档的澄清问题质量），它需要**真人**评审——AI 不能代替真人做
「人工盲评」，那会让这个词本身变成谎报。**这一项留待人工评审后另行发布。**
