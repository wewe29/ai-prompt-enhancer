# PromptCraft v0.4.1 — 提示词与评测工具（**不含效果验证**）

> **本版本不宣称任何效果数字。**
> 本版只包含提示词修订与评测工具增强，**未做效果验证**；
> 上一版（v0.4.0）的 41 条「把失败显示成成功」闭环结论保持不变。
> 效果线在 v0.4.2。

---

## 1. 这个版本做了什么

一句话：**给「禁止提问用户已经说过的信息」这条规则装上机器可判的尺子。**

### 1.1 提示词 `promptcraft-v2.2.0` → `promptcraft-v2.5.0`（只追加，不改写既有条款）

在第 8 条之后追加了一段「问题自检」和 4 条典型反例。要点：

- 每个问题输出前逐条过：答案**是否已经在用户原文 / 上下文 / 附件里**？
  是 → 删掉。用户已经给过的信息不是缺失信息。
- 答案能否由**合理默认**推断出来（且推断错了也不影响产出）？是 → 删掉。
- 删完后问题数为 0、且缺失信息并不影响产出时 → 改判 `none` / `light`，
  **不要为了凑问题而提问**。

反例直接点名了最常见的几种多余提问：

| 用户已经说了 | 不该再问 |
|---|---|
| 「帮我翻译一下」 | 「要翻译的原文是什么」 |
| 「这段录音 / 这份文档 / 这段代码」 | 「内容在哪里 / 请上传 / 请粘贴」 |
| 「帮我改一下」（内容已贴出） | 「你想改哪里」 |
| 「写个方案」（主题已给） | 「方案的题目是什么」 |

> `v2.3.0` 与 `v2.4.0` 是两次已废弃的判据实验，历史记录与实验文档均已引用，
> **不复用**，故直接落到 `v2.5.0`。

三处同步：`src-tauri/src/prompts.rs`（运行时唯一来源）、`evaluation/enhancer.py`
（评测侧复刻）、`src/App.tsx`（前端）。

- Rust 与 Python 之间**逐字**相等，由 `evaluation/test_enhancer.py` 断言。
- **前端此前没有任何测试保护它** —— 它把版本号写进历史记录的 `promptVersion`，
  漂了就是在写一个不存在的版本号，而没有任何东西会报警。
  现补上 Rust↔TS 跨源断言与 `src/promptVersion.test.ts`。

### 1.2 样本集新增「不该问什么」的标注

`evaluation/samples_v30.yaml` 的 20 条 severe 样本全部新增 `must_not_question` 字段，
标的是「**答案已经出现在用户原话里**」的提问内容。

- 每条 1–3 条；能确定就填，不确定就留空。
- **宁可漏填，不要凑数** —— 误标会产生假阳性，让门禁失真（比没有门禁更坏）。
- 20 条里 **8 条有标注、12 条留空**；其中 3 条翻译样本是规格强制填写的
  （那是唯一被实测证实的失败模式）。

### 1.3 评测新增第六个机械判定维度

`evaluation/verify_enhance.py` 新增 `redundant_question` 维度，与既有五维并列：

- 归一化后子串匹配（复用既有 `normalize_for_match`）；
- 命中任一 `must_not_question` ⇒ **严重问题**；
- `must_not_question` 缺失或为空 ⇒ 记「**无标注-不判定**」，
  **不得记为通过** —— 否则未标注样本混进分母，门禁会造出虚假绿灯；
- 汇总时「无标注-不判定」单独成桶，**不计入通过**。

> 这个维度是**保守的下限**：子串匹配只抓字面复现
> （「要翻译的原文是什么？」确实含「原文是什么」✓），
> **改写过的问法会漏报**。它是下限证据，不是全量判据。

### 1.4 门禁规范补齐事实

`evaluation/gate_spec_v040.json` v040.1 → v040.2：

- 每条 active 门槛新增 `n_unit`，把 n 的单位**钉死**：
  G4/G5 是**问题条数**、G6 是**样本条数**、G7 是**运行次数**。
  此前这些单位只能从基线值（如 `44/60`）反推，装配测量值时极易把
  「样本数」和「问题数」搞混 —— 而门禁一旦拿错分母，判定就是错的。
- G5 / G6 新增 `known_gap`，把「在现有样本集下结构性不可达」这件事
  **登记在规范里**，并由 `gate_spec_report.py` 直接打印出来，
  而不是只藏在 JSON 里。

### 1.5 发布工作流参数化

`.github/workflows/release.yml` 的发布说明改为按版本号取
`release-assets/RELEASE_NOTES-<version>.md`，发布标题不再写死某一版文案
⇒ **新版本不需要再改这个工作流文件**。
`body_path` 指向的文件不存在时必须失败（`fail_on_unmatched_files`），
不允许静默发一个空说明。

## 2. 为什么这一版没有效果数字

三条原因，都写得很具体：

1. **本版是前置。** 它装的是「尺子」（提示词规则 + 标注 + 机械判定），
   不做测量。尺子刚装上就报效果，等于拿新尺子第一次量的数当结论。
2. **v0.4.0 已把档位稳定性那三条门槛正式作废**（间距小于噪声地板 ⇒ 不可判定）。
   作废不等于通过，也更不等于「已经改善」。
3. **效果线的两条门槛在现有样本集下结构性不可达**，这一点已写进门禁规范的
   `known_gap` 并由推导报告打印：G5 需要 68 个**问题**，而 severe 档
   20 条样本最多只有 60 个；G6 需要 61 个**标注样本**，而 severe 样本总体只有 20 条。
   ⇒ 效果线必须先做一次**可达性核算**（扩样本还是改口径），再开跑。

顺带说一句：**v0.4.1 的提示词改动会让 severe 档转澄清的条数变少**
（自检规则第 3 条明写「不要为了凑问题而提问」），
所以可评的问题数只会更少 —— 缺口不会自己消失。

## 3. 怎么验证这一版

```
python scripts/check-fail-open.py      # OPEN 0 / FIXED 41 / UNVERIFIED 0，退出码 0
python -m pytest evaluation -q         # 评测侧回归
npm test                               # 前端回归
cargo test --manifest-path src-tauri\Cargo.toml
cargo fmt --manifest-path src-tauri\Cargo.toml --all -- --check
python evaluation/check_gate_behavior.py    # 门禁行为级复核
python evaluation/gate_spec_report.py       # 门槛推导（含已知缺口）
```

以上全部在 GitHub Actions 的发布工作流里跑，**跑不绿就不发**。
构建在 GitHub 的 runner 上完成，**发布不依赖任何一台机器的网络**。

## 4. 升级说明

- 绿色版：解压后直接运行 `PromptCraft.exe`，覆盖旧目录即可。
- 无配置迁移，无数据格式变化，历史记录不受影响。
- 提示词版本号会从 `promptcraft-v2.2.0` 变成 `promptcraft-v2.5.0`，
  历史记录里会如实显示新版本号。
