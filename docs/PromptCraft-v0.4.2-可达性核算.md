# PromptCraft v0.4.2 阶段 A —— 可达性核算

> **本文件不含任何效果结论。** 它回答的是一个问题：
> **「按现有样本集，门槛 4/5/6 还差多少？跑盲评之前要不要先改样本集或改口径？」**
>
> 证据：`docs/evaluation-data-v042/`（原始产物 + 结论 + 校验和）
> 工具：`evaluation/v042_reachability.py`（0 次 API 调用）
> 运行身份：`promptcraft-v2.5.0` / `deepseek-flash` / temp 0.1 / samples_v30.yaml / 60 条 / 1 次运行

---

## 0. 结论（先说结果）

1. **v2.5.0 的自检规则确实生效了**，而且生效得比预期猛：
   severe 档转澄清从 20 条降到 **17 条**，可评问题从 60 个降到 **48 个（−20%）**。
2. **门槛 4 刚好卡线**（翻译场景可评 5 个问题，要求正好 5 个）——
   **任何一个字的变化都会掉下去**。
3. **门槛 5 与门槛 6 在现有样本集下不可达**（缺 20 个问题 / 缺 53 个标注样本），
   而且**门槛 5 的要求量本身依赖样本集**（required_n 由基线推导，基线要在同一样本集上测）
   ⇒ 存在循环依赖，必须先定「样本集长什么样」。
4. **第六维报「0 命中」是字面口径的 0，不是语义口径的 0**：
   8 条标注样本逐条人工过，**至少 1 条确定漏报**（`v30_translate_two_versions`）。
   ⇒ **先修判据口径，再谈样本量**。

## 1. 实测数据

### 1.1 v2.5.0 相对 v0.4.0（v2.2.0）的规模变化

| 指标 | v0.4.0（v2.2.0） | v0.4.1（v2.5.0）实测 | 变化 |
|---|---|---|---|
| severe 档样本 | 20 | 20 | — |
| ├─ 转澄清（有提问） | 20 | **17** | **−3** |
| └─ 未转澄清 | 0 | **3** | +3 |
| severe 可评问题总数 | 60 | **48** | **−12（−20%）** |
| 翻译场景可评条数 | 3 | **2** | −1 |
| 翻译场景可评问题数 | 9 | **5** | **−4（−44%）** |
| 有 `must_not_question` 标注的样本 | 0（当时未标） | 8 | — |
| 第六维命中 | 20 条里有 **2 条**问题全部冗余（0/3） | 字面 **0** / 语义 **≥1** | 见 §3.3 |

**未转澄清的 3 条**（这是自检规则生效的**独立观察值**，不混进任何命中率）：

| 样本 | 原话 | 判档 | 判档理由（对照 SPEC §4.2 反例） |
|---|---|---|---|
| `v30_office_report_summary` | 帮我把这个文档总结一下，做完发我。 | light | 反例「用户说『这份文档』→ 禁止问『内容在哪里/请上传/请粘贴』」⇒ 不问，直接产出带占位的提示词 |
| `v30_translate_audio_transcript` | 把这段会议录音翻译成英文，我后面要用。 | light | 同上（「这段录音」） |
| `v30_creative_birthday_poem` | 写一首诗送给朋友。 | light | 写诗本就不缺关键信息，判 light 合理（与自检规则无关） |

### 1.2 门槛对账（缺口表）

| 门槛 | n 单位 | 要求 n | 要求 R | 实测 n | 缺口 | 可达 |
|---|---|---|---|---|---|---|
| G4 翻译场景人工盲评命中率 | questions | 5 | 2 | **5** | **0** | **刚好卡线** |
| G5 severe 整体人工盲评命中率 | questions | 68 | 2 | **48** | **−20** | 否 |
| G6 严重档「问已知信息」条数 | samples | 61 | 1 | **8** | **−53** | 否 |

G6 的 0 命中上界：3/8 = **37.5%**，而规范自设的认证上限是 5% ⇒ **证不到**。

### 1.3 G5 的外推

按实测「每单元 2.82 个问题」外推：68 个问题需要约 **24 个**转澄清的 severe 单元，
当前 17 个 ⇒ **还需新增约 8 条 severe 样本**（且它们必须都转澄清）。

> 这是**外推**，不是保证：新增样本不一定都转澄清，扩完必须重跑核算。

## 2. 三个结构性缺口的性质变了

### 2.1 缺口 C 兑现了，而且比预估更严重

Plan §1.3 的缺口 C 预测「v2.5.0 会让 severe 转澄清条数下降 ⇒ G5 的分母下降」。
实测确认：**问题数下降 20%，翻译场景问题数下降 44%**。

⇒ 缺口 A（G5 缺 20 个问题）**不是「差 3 条样本」**，而是**差 8 条**。

### 2.2 门槛 5 的 required_n 本身依赖样本集（循环依赖）

`required_n = required_n_two_proportions(baseline, 0.85)`，
而 **baseline 必须在同一样本集上测**。于是：

```
扩样本 ⇒ 样本集变了 ⇒ 基线要重测 ⇒ required_n 要重推 ⇒ 还差多少要重算
```

更糟的是：**基线越高（间距越小），required_n 越大**。
若 v2.5.0 把命中率抬到 80%，间距从 12 点缩到 5 点 ⇒ required_n 从 68 涨到 ~367。

⇒ **「先扩到 68 个问题」这条路，本身依赖一个尚未测出来的基线。**
必须先定「严重档样本集长什么样」，才谈得上扩多少。

### 2.3 门槛 6 无论怎么扩都认证不到 5%

现有 20 条 severe 里只有 8 条可标（可标注率 40%，因为「答案已在原话里」
这个属性只在「引用型」句式里天然成立）。要凑 61 个标注样本：

- 按 40% 可标注率 ⇒ 需要 severe 样本集扩到 **~150 条**；
- 即使按「全部新样本都可标」的最乐观假设 ⇒ 也要 **20 + 53 = 73 条**。

⇒ 而 severe 样本集一旦被「可标注型」样本主导，
**门槛 5 的「severe 档整体」就不再是 severe 档整体**（构成失真），
门槛 5 的历史基线（44/60）也一并失效。

⇒ **门槛 6 与门槛 5 的样本需求是互相冲突的。**

## 3. 三个新发现

### 3.1 自检规则确实生效（正面）

翻译 3 条的对照最清楚：

| 样本 | v0.4.0（v2.2.0） | v0.4.1（v2.5.0）实测 | 判定 |
|---|---|---|---|
| `v30_translate_generic` | 问「要翻译的原文是什么？」 | 问「译文输出成哪种语言/原文是哪种语言/专有名词是否保留」 | **生效** |
| `v30_translate_audio_transcript` | 问「这段会议录音的内容在哪里？请粘贴转写文本或上传音频」 | **判 light，0 问** | **生效** |
| `v30_translate_two_versions` | 1/3 命中 | 问「请把需要翻译的原文直接发给我，或指明它在附件/上下文中的位置」 | **漏了**（见 §3.3） |

⇒ 失败模式「问用户已经知道的事」**从「每次都犯」降到「换个说法还犯」**。

### 3.2 严重档的问题数不是「质量指标」，是「分母」

3 条 severe 不再转澄清，看起来是好事（不为了凑问题而提问），
但**它们同时把这 3 条从人工盲评的分母里拿掉了**。
⇒ v0.5.0 之前那个「把档位决策从 LLM 手里拿走」的主线，
现在多了一个具体的理由：**档位变化会直接改掉效果门的分母。**

### 3.3 第六维有漏报（必须写进口径）

8 条标注样本共 16 个问题，字面匹配 **0 命中**。逐条人工过：

| 样本 | 问题 | 字面 | 人工判定 |
|---|---|---|---|
| `v30_translate_two_versions` | 「请把需要翻译的原文直接发给我，或指明它在附件/上下文中的位置。」 | 无 | **冗余（确定漏报）** —— 正是 SPEC §4.2 反例禁止的「内容在哪/给我」 |
| `v30_translate_generic` | 「译文要输出成哪种语言？原文是哪种语言？」 | 无 | 必要（问的是源语言，用户确实没说） |
| `v30_code_refactor_goal` | 线上问题表现 / 语言框架版本 / 优化边界 | 无 | 三问都必要 |
| `v30_code_contradictory` | 语言框架依赖 / 50ms 口径 / 瓶颈类型 | 无 | 三问都必要 |
| `v30_qa_compare_plans` | 两个方案的核心内容 / 决策看重什么 | 无 | 两问都必要 |
| `v30_data_analyze_excel` | 分析目的 / 表间关联 / 交付偏向 | 无 | 三问都必要 |
| `v30_office_report_summary` | （0 问） | — | 无提问 |
| `v30_translate_audio_transcript` | （0 问） | — | 无提问 |

⇒ **漏报率 1/8 = 12.5%（按问题计 1/16 = 6.25%）**。
⇒ **「0 命中」只能写成「在这 8 条标注样本上，字面复现没发生」**，
不能写成「不再问已知信息」。

## 4. 决策点落定方案

### D1（G6 口径）→ **选 (a)：降口径为下限证据**

G6 补到 61 个标注样本要求 severe 样本集扩到 73~150 条，
且会把「severe 档整体」的构成抽干 ⇒ 与门槛 5 直接冲突。

**采用**：G6 拆成两段语义——
- 「**有标注样本上命中即失败**」保持 active，参与放行；
- 「**真实冗余提问率 ≤5% 的认证**」降为非 active，显式列在门禁输出里
  （`status != "active"` ⇒ 不参与放行但必须打印，代码已支持）。

**宣称口径**（写进 v0.4.2 的发布说明）：
> 「在 N 条标注样本上，**字面复现**的冗余提问为 0；95% 率上界 ≈ 3/N = X%。
> 这是**下限证据**——已知存在改写式漏报（实测 1/8），故**不等于**『不再问已知信息』。」

### D2（标注范围）→ **选 (a) 维持 8 条 + 补口径说明**

- 不为了凑数把 12 条空标注填上（误标产生假阳性，比没有门禁更坏）。
- **必须补**：在 gate spec 的 G6 note 与发布说明里写明「字面下限 + 已知漏报」。

**可选增强（阶段 B 决定）**：把标注从「完整问法」改成
「**索要对象 + 动作**」两个槽（如 object=原文 / action=提供|粘贴|上传|在哪），
匹配时按槽组合 ⇒ 可覆盖改写。代价是要重标 8 条，且仍有漏。

### D3（样本集怎么办）→ **推荐路径 2，但分两层，且要用户拍板**

**路径 1：保持 20 条 severe 不变**
- 门槛 4：n=5 刚好卡线，**脆弱**；
- 门槛 5：48 < 68 ⇒ **永远不可达**，只能降口径；
- 门槛 6：8 < 61 ⇒ **永远不可达**，只能降口径。
- ⇒ 代价：三个门槛里**两个永久降级为下限证据**，且门槛 4 随时可能因运行间漂移掉到 4。

**路径 2：扩样本（推荐）**
- **第一层（补余量，必须做）**：新增 **+3 条翻译类 severe** ⇒
  翻译场景 n 从 5 → ~8~9，脱离卡线；这 3 条按翻译 3 条的模式带标注
  （可标注率 ~100%）⇒ 顺带把标注样本从 8 提到 ~11。
- **第二层（补门槛 5 的量）**：新增 **+8 条其他场景 severe**（保持构成代表性，
  不走「全翻译化」）⇒ 预计问题数 48 → ~72~75，重新推导 required_n 后再核对。
- 合计 severe 20 → 31 条，重跑 ~71 次 API 调用。
- ⚠ **但门槛 6 仍认证不到 5%**（标注样本 ~16，3/16 ≈ 18.8%）⇒ D1(a) 仍需执行。

**无论走哪条，门槛 6 都要按 D1(a) 降口径。**

---

## 5. 需要你拍板的三件事

1. **样本集**：走路径 1（不动 20 条，两个门槛永久降级）还是路径 2（扩到 31 条）？
   - 路径 2 还要定：新增翻译类 severe 用什么句式（要保证「答案已在原话里」可标注），
     以及其他 8 条分布在哪些场景。
2. **G6 口径**：确认按 D1(a) 降为「下限证据 + 字面下限声明」？
   （不降的话需要 severe 样本集扩到 73~150 条，且构成失真。）
3. **人工盲评的人**：门槛 4/5 要求 R≥2。首选 **2 名独立评审人各一轮**；
   只有 1 人时必须两轮且结论里写明「轮间与人间方差未分离」。

## 6. 本阶段的边界

- **没有**跑人工盲评，**没有**任何 `v040_gates` 测量值，**没有**效果宣称。
- 本目录的数字（48 / 5 / 8 / 0）**不是**效果指标，是**分母与可达性**的核算。
- v2.5.0 的数据**不可**与 v0.4.0（v2.2.0）的数据直接比较：
  提示词正文参与运行身份哈希（`prompt_sha256`），两者身份不同、不可混跑。
- 本文里对「哪些问题是冗余」的人工判断**不是**盲评结果，
  只用于证明第六维有漏报，**不能**用来替代门槛 4/5 的盲评。
