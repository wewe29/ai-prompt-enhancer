## Phase 1: Rust 后端解析流水线与降级交付

### Task 1.1 新增结果字段(models.rs)
- 在 `EnhancementResult`(models.rs:31-47)追加:
```rust
#[serde(default = "default_delivery_status")]
pub delivery_status: String,        // complete | partial | fallback
#[serde(default = "default_enhancement_level")]
pub enhancement_level: String,      // none | light | clarify
#[serde(default)]
pub notices: Vec<String>,
```
- 默认函数:`default_delivery_status() -> String { "complete".into() }`、`default_enhancement_level() -> String { "light".into() }`。
- 更新 provider.rs 测试构造体(models 字段同步)。
- 验证:`cargo test`(既有 6 项)。

### Task 1.2 四步解析流水线(provider.rs)
把 `parse_result` 替换为三个新函数 + 归一化:
1. `parse_enhancement(raw) -> Result<Value, String>`:依次尝试 ① 完整 `serde_json::from_str` → ② 剥 ` ```json/``` ` 围栏再解析 → ③ **字符串感知平衡花括号扫描器**截取首个完整对象。扫描器规则(写单测):跳过字符串内 `{`/`}`;处理 `\"` 与 `\\`;对象未闭合→返回 Err,不 panic、不越界。**禁止** 保留"首 `{` 到末 `}`"作为最终算法。
2. `normalize_value(value) -> (Value, Vec<String>)`:status 非法/缺失按 `questions` 非空推导;task_type 非法→`other`;数组 null/类型错→空数组+notices;`suggestions>5` 截断前 5、`<5` 保留现有;**重复 id 去重后续条目**+notice;questions>3 截断;missing id 用 `sN/cN` 补齐;`primary_prompt.trim()` 清理。
3. `validate_core_result(&EnhancementResult) -> Result<(), String>`:仅 primary_prompt 非空、无 `XXX`、status 合法、questions≤3。
4. `validate_complete_result(&EnhancementResult, original: &str) -> Result<(), String>`:suggestions 恰好 5、kind/operation/id 合法、changes.before 需在 original 中找到(空 before 仅允许 add_context/add_constraint/format/safety)、task_type/enhancement_level 合法。

- **重写 `enhance()` 主流程**(provider.rs:50-107):解析→归一化→核心校验;核心通过后完整校验→`complete`,失败→`delivery_status=partial`+notice,仍发 Result;核心失败→attempt0 重试(见 1.3)→仍失败→用 `partial_primary_prompt` 提取构造 partial 或构造 fallback(primary=original_text,数组全空,notice "增强服务未返回可用结构，本次已保留原始提示词"),**总是发送 Result 事件**,返回 `Ok(())`。
- 校验：`cargo test`;新增 10 项单测(见 Phase 5)。

### Task 1.3 结构修复重试 + 错误码
- 第二次请求不重复原请求:user message 追加专门修复指令(规格 §4.3 第四步原文)。修复消息不含敏感正文。
- 新增错误码常量表(规格 §4.4 12 个码)与 `record_error_usage(code)`;失败路径调用 `record_usage(status="error", error_code=Some(code))`;用户取消不报错(已有 `Ok(())` 路径,保留)。
- `map_http_error`(provider.rs:356-373)改为集中映射到错误码 + 中文文案(前端只显示文案)。
- 验证:单测覆盖 STRUCTURE_FALLBACK/STRUCTURE_PARTIAL/USER_CANCELLED 路径。

### Task 1.4 提交
- 独立提交:`refactor: split core and complete enhancement validation`、`fix: recover partial structured enhancement results`、`feat: add fallback delivery status and notices`。
- 每提交后 `cargo test`。

## Phase 2: 前端降级体验与兼容

### Task 2.1 类型与 schema
- `types.ts:44-53` `EnhancementResult` 增 `delivery_status?: "complete"|"partial"|"fallback"`、`enhancement_level?: "none"|"light"|"clarify"`、`notices?: string[]`;`HistoryRecord`(types.ts:91-99)增可选 `deliveryStatus/enhancementLevel/promptVersion`。
- `schemas.ts:7` 对应 zod 字段:`delivery_status` enum default `"complete"`、`notices` default `[]`;`enhancement_level` 不在 zod 里给静态默认(需按 status 推导,见 2.2)。
- `lib.ts`:`blankResult`、`mockResult` 补新字段。

### Task 2.2 normalizeResult 兼容映射(lib.ts:204-206)
- normalize 前预处理旧结果:无 `delivery_status`→`"complete"`;无 `enhancement_level`→`needs_clarification? "clarify" : "light"`;无 `notices`→`[]`;再走 zod parse。
- 保持 `safeParseResult` 行为(测试 lib.test.ts 需同步兼容旧数据,新增一条旧格式用例)。

### Task 2.3 App.tsx 状态处理
- result 事件(App.tsx:168-181)按 `delivery_status` 分支:
  - `complete` → 现状(ready + persistHistory)。
  - `partial` → state `ready`,输出 primary_prompt,notices 透传,persistHistory 正常。
  - `fallback` → 输出=primary_prompt(=原文),state `ready`,文案"已保留原文",`persistHistory` 写入 `deliveryStatus:"fallback"`(历史视图显示"原文回退"徽标)。
- normalize throw(现状 catch)→ 不再只报错:输出为空则置为 `original` 草稿,state `incomplete`,notice "已保留你的输入，可重新生成";不落历史。
- 新增三个 handler(均走 `commitOutput` 进撤销栈):
  - `restoreOriginal()`:输出=本次请求开始时的 original。
  - `keepEssentialEdits()`:仅在存在 accepted/pending changes 时显示;拒绝所有非 safety 且未明确接受的 change,按 change 规则重建输出。
  - `regenerate()`:沿用当前 input/config 重调,不清 original/context/attachments。

### Task 2.4 EnhanceView 按钮与 notices
- 结果区顶部渲染 notices 条(非模态、去重;partial/fallback 至少一条)。
- 新增按钮:恢复原文(恒显,输出非空时)、仅保留必要修改(有 accepted/pending changes 时)、重新生成(恒显)。
- 复制/编辑按钮在 partial/fallback 下保持可用。
- 前端测试:规格 §4.6 六项(旧格式兼容、partial 可复制、fallback 显示原文、恢复原文进撤销栈、重新生成不清上下文、停止不显示失败)。

### Task 2.5 提交
- `feat: expose enhancement level and result metrics`、`feat(ui): recoverable fallback and restore buttons`。
- 每提交后 `npm test && npm run build`。

## 反模式守卫
- 不使用未在文档中的 API/参数(新字段一律 serde default;zod 一律 default)。
- 不保留"首 { 到末 }"解析;平衡扫描器必须处理转义。
- 不把"恰好 5 条建议"作为核心成功条件(仅完整校验)。
- fallback 不得本地编造 suggestions/changes/questions。
- 前端错误分支不得依赖内部错误码字符串(仅显示中文文案)。
- 所有 result 路径必须发送 Result 事件,不得在可交付时抛异常。
