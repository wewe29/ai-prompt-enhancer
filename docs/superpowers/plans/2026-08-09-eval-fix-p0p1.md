# 评测体系 P0/P1 修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按用户评审意见修复评测体系 P0/P1 问题:样本结构(补齐场景/难度化画像/真实粗糙 prompt)、裁判升级(prompt 级评分/改进幅度/交叉验证/显著性)、生成参数(temp 差异化/增强器解耦/长度控制组/token 成本)、评分公式(去重复权重/延迟降权/类别权重)、回归测试集。

**Architecture:** 修改集中在 `evaluation/` 的五个层:样本层(samples.yaml/personas.yaml/新增回归集)、裁判层(judge.py/bench_judge.py 增加 prompt 级评分、幅度、双裁判、novelty 维度)、管线层(run_eval.py 增加 per-scenario temp/控制组/prompt 级评分接线)、聚合报告层(report.py/bench_report.py 修正公式、加置信区间/成本/回归率)、配置层(config.yaml/benchmark_config.yaml)。

**Tech Stack:** Python (evaluation harness), Volcano Ark API (Anthropic + OpenAI 兼容)。

### Task 4 (J1): prompt 级评分(直接评增强后的 prompt)

**Files:** Modify: `evaluation/judge.py`(新增 `judge_prompt_level`)、`evaluation/run_eval.py`(接线)、`evaluation/report.py`(报告章节)

- [ ] **Step 1: judge.py 新增 `PROMPT_JUDGE_SYSTEM_PROMPT`**(中文,单对象评分,输出 JSON):
  - `structure`(结构清晰度):角色/任务/约束/输出格式是否分层明确
  - `constraint_retention`(约束保留率):原始 prompt 的约束是否完整保留
  - `info_gain`(信息增益):是否补充了合理隐含需求(编造则扣分)
  - `over_enhancement`(过度增强):是否添加原始没有的约束/偏见(高分=过度)

- [ ] **Step 2: run_eval 增强阶段后调用**(每样本 1 次裁判调用,缓存 `prompt_judge_<pid>.json`,`--skip-prompt-judge` 跳过)

## 风险与对策

| 风险 | 对策 |
|---|---|
| doubao-seed-2-1-pro 在 plan 端点不可用 | 增强器走已验证的 /api/v3(openai)协议 |
| novelty 维度拉低裁判稳定性 | 缺失回退 novelty=relevance;聚合层容错 |
| 双裁判/控制组成本翻倍 | 默认关闭,按需开启;max_cost_usd 预算保护已有 |
| 旧缓存与新 schema 不兼容 | prompt 级/novelty/控制组使用新缓存键;旧键不冲突 |
