**这就是"三次尝试改判据都失败"的机制性解释之一**：测量层没有一种统一的"这里没测到"的表达方式，于是每次改判据，改的都是某个具体位置的默认值；下次换个地方重演同一个错误，团队就以为"判据本身有问题"。**先统一缺失的语义，再谈改判据。**

## 1. 唯一的合法缺失表示

> **缺失 = `None`（Rust: `Option::None` / Python: `None` / TS: `null`）。**
> **没有任何其他东西可以表示"没有"。**

配套的两个必要区分：

- **观测到的 0 不等于缺失。** 0 次失败就是 `0`，它必须能和"没测到"区分开。缺失用 `None`，零用 `0`，两者不得互相顶替。
- **空集合不等于缺失。** `[]` 表示"测了，结果是空的"；缺失表示"没测"。在 Python 侧，`[]` 与 `None` 都在 JSON 里可以区分；在 Rust 侧 `Vec::new()` 与 `Option::None` 必须用不同类型区分。

## 2. 六种伪装（缺陷侧的六种表现）

下表是本项目里实际出现过的全部六种伪装形式，每种都给出实例位置。

### D1 零值伪装

缺失被写成 `0` / `0.0` / `false`。

```
evaluation/report.py:350   "pad_ratio": ... if cost_ratios else None    # 已修（正例）
evaluation/report.py:236   mean_delta = (sum(deltas.values()) / len(deltas)) if deltas else 0.0
evaluation/report.py:300   dim: round(sum(vals) / len(vals), 4) if vals else 0.0
```

**为什么最危险**：0 是一个**合法的好数字**。下游的门槛判断（`pad <= 2.0`、`worse_rate < 0.1`）拿 0 去比，天然通过。**缺失一旦变成 0，判定层就再也发现不了它。**

### D2 空串伪装

```
evaluation/export_data_pack.py:74   "...胜/平/负 = 4/3/5..."   # 整段是字面量，与数据无关
```

### D3 空容器伪装

```
evaluation/report.py:186   enhanced = sample.get("enhanced")      # 缺失时是 None
evaluation/report.py:209   deltas = judge.get("deltas", {})        # 缺失时是 {}
```

`{}` 与 `None` 在下游走同一条分支，于是"没给维度分"和"给了空维度分"无法区分。

### D4 键不存在伪装

```
evaluation/verify_enhance.py:214   q.get("question", "")   # Rust 侧字段名其实是 text（models.rs:68-72）
```

读取端用一个**猜错的键名**去取，取不到就得到空串 —— 字段不存在被伪装成"这个字段是空的"。**这一类只能用跨层等价测试发现，读代码看不出来。**

### D5 默认值伪装

缺失被补上一个"看起来正常"的默认值。危害排第二，因为它产出的是**语义错误**而不是数值错误。

```
evaluation/enhancer.py:211    out.setdefault("enhancement_level", "clarify" if ... else "light")
src/lib.ts:242                enhancement_level: result.enhancement_level ?? (... : "light")
src-tauri/src/storage.rs:131  .unwrap_or_default()          # 配置读失败 → 默认 ProviderConfig
evaluation/bench_judge.py:89  value = parsed.get("relevance")   # novelty 缺失 → 用 relevance 顶替
```

其中"指标被顶替"（relevance 顶替 novelty）最阴险：**顶替后的数值完全合法，且参与模型排名的排序键**，没有任何报错。

### D6 分母消失伪装

样本不是被写成零，而是**从分母里消失**。这是最难发现的一种，因为所有指标看起来都自洽。

```
evaluation/report.py:211   judge = result.get("judge"); if not judge: continue
evaluation/report.py:198   if isinstance(enhanced, dict) and enhanced: delivery_total += 1
evaluation/report.py:396   present_min = min((n for sc, n in scenario_ns.items() if sc in major_scenarios), default=None)
```

第三行尤其典型：只对**已经出现过的场景**取最小值。跑 20 条编程、0 条办公写作，`present_min = 20`，门槛通过 —— **缺失的场景不参与取 min，等于不存在。**

## 三之二、逐条点名：哪些是「表示法不统一」，哪些是「独立逻辑错误」

> 这是 WP3-2 明确要求的一条：**约定能一次性关掉哪些，必须逐个单独改哪些。**
> 范围 = `docs/v040-失败伪装清单.json` 的**全部 41 条**（清单已从原报告的 20 处扩到 41 条，覆盖面只增不减）。
> **分类依据是"机制"，与当前是否已修复无关**（A1/A2/A3/E2/E3/E4/E5 已 FIXED，但机制分类不变）——每条的当前状态见 `docs/v040-失败伪装-分级与验收条件.md` §二之二。

### 两类的判据

| | **类 1：表示法不统一** | **类 2：独立逻辑错误** |
|---|---|---|
| 根因 | "缺失/未知/失败"被用某个**具体值**表示出来 | 判断逻辑、业务规则、边界、契约、信任边界本身错了 |
| 典型形态 | `0.0` / `"complete"` / `"light"` / `"none"` / 默认配置 / `continue` 掉 / 0 参与平均 / 复制一个值充数 | 键名写错、集合映射不可区分、断言恒真、契约缺变体、信任边界缺失、状态机时序错 |
| 约定能否救 | **能**：按 R1–R8 统一改表示 + fail-closed，一次收口 | **不能**：必须逐条改；改完之后约定只负责**防止同类复发** |
| 改法 | 改表示 + 补 fail-closed 判定 | 各自要单独的设计判断 + 行为级回归测试 |

### 一句话结论

> **29 条靠约定收口，12 条必须逐个改。**
> 如果只立约定不做类 2 的逐条修改，**发布判定仍然会失真**——因为 B1（判据不可区分）、E5/G10（信任边界）、G9/G11/G12（状态机与文案）这 6 条与"缺失表示"无关。

|---|---|
| 失败原因以**独立字段**表达（`error_code`、`notices`、`delivery_status`） | 把失败编码成业务正常值（`enhancement_level: "none"`） |
| 每个样本无论成败都进入统计分母 | `continue` 跳过失败样本 |
| 记录 `status`（success / error / partial） | 把 error 记成 success，或用 0 代替成本 |

> `provider.rs:854/872` 的 fallback 结果必须携带独立的失败原因字段，`enhancement_level` 只允许来自模型判断。

### 4.2 存储层（`src-tauri/src/storage.rs`）

| 允许 | 禁止 |
|---|---|

| 返回结构化报告（`imported` / `skipped`） | 静默 `take(N)` 截断 |

### 4.3 聚合层（`report.py`、`bench_report.py`、`judge.py`、`bench_judge.py`）

| 允许 | 禁止 |
|---|---|
| 指标缺失 → `None` | `else 0.0` |
| 指标缺失 → 从排序键里退出（该模型标为不可评） | 用别的指标顶替（relevance → novelty） |

### 4.5 呈现层（`report.py` 的 Markdown、`src/views/*.tsx`）

## 6. 例外与豁免

1. **真实 0**：0 次失败、0 个候选、0 成本是合法观测值，用 `0` 表示，不得改成 `None`。判断标准是"我们测过了"。
2. **错误码与提示**：属于"已知的失败"，用独立的 `error_code` / `notices` 字段表达，不占用数值字段。
3. **UI 的"未配置"**：前端未配置状态不属于测量缺失，可用 UI 专有的 `null` + 空态渲染，但**不得复用业务字段**。
4. **历史遗留产物**：v0.3.2 及以前已产出的 JSON 不回改；它们只能标注为"历史产物，口径见 v040-效果测量方案.md"，不得与 v0.4.0 产物混算。
