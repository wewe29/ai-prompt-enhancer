# PromptCraft v0.3.3 迭代实施规格：增强结果体验

> 文档状态：可直接实施  
> 基于版本：PromptCraft 0.3.2  
> 适用项目：`F:\ai-prompt-enhancer`  
> 编写日期：2026-09-06  
> 上游依据：`docs/PromptCraft-v0.3.1-v0.5.0-iteration-spec.md` §5（v0.3.3 原始要求）；`docs/PromptCraft-v0.3.2-评测报告.md`（本轮新增的体验修正依据）

## 1. 文档目的

v0.3.3 的目标是「优化增强结果展示和降级体验」。原始要求见上游规格 §5，本轮将其细化为可直接实施的行为要求，并补齐三块原始要求未覆盖的内容：

- 上游规格只给了「必须显示 / 必须提供」清单，本轮逐条核对前端现状，给出已实现项与真实差距，避免重复实现。
- v0.3.2 可信评测得出两条影响体验设计的结论：清晰任务被增强后明显变差率达 41.1%；自动评测胜率虚高的主因是 LLM 裁判对更长回答的系统性偏好（增强膨胀 ×4.63）。据此新增 4.6 的两个体验修正——`none` 等级引导保留原文、结果过长时提示精简。
- 上游规格要求显示「用户原始事实」「当前候选提示词编号」「候选切换」，但现有 `EnhancementResult` 没有对应字段，本轮定义 `facts` / `candidates` 两个新增可选字段及其后端产出方式。

本轮按用户要求**不含测试与验收内容**：测试与验收方案暂缓制定，见 §8 备注。

## 2. 当前基线与差距

### 2.1 已实现（本轮只验证不回退，不重做）

以下能力已在 0.1.0–0.3.0 交付，本轮不得破坏：

- 增强等级显示（none/light/clarify → 中文摘要行）、字数变化（含倍率）、修改摘要（由 changes 推导）、模型假设展示。
- 逐项接受 / 逐项拒绝修改（锚点未命中提示「原文已被编辑」，不静默改动）。
- 恢复原文、仅保留必要修改（safety 类 + 已接受项）、重新生成。
- 手动编辑（输出框任何状态可编辑）、撤销 / 重做（快照上限 100，Ctrl+Z / Ctrl+Shift+Z·Ctrl+Y）。
- partial/fallback 六项降级体验：非阻塞 notices、保留原始输入、复制可用、不清空附件、不阻止手动编辑、字段级缺失提示由后端生成并透传。
- 三轮澄清：当前轮次显示、留空跳过、结束澄清保留临时结果、needs_clarification 仍带可用的临时主提示词与 assumptions。
- `Suggestion.kind` 五类枚举（goal/context/format/constraint/alternate_intent）在类型、zod schema、后端提示词三处一致。

### 2.2 真实差距（本轮要做的 8 项）

| # | 差距 | 现状证据 |
|---|---|---|
| 1 | 交付状态无显式显示：complete/partial 完全不可见，仅 fallback 经 notices 间接体现 | 结果区仅有 CSS 修饰类，无徽标/文字行 |
| 2 | 用户原始事实无展示：无 `facts` 字段，现「事实来源」只是「有无 assumptions」的二值推导 | 结果摘要行文本，非事实清单 |
| 3 | 风险提示 UI 零渲染：`risk_flags` 数据链路完整（类型、zod、后端产出、前端归一化保留）但视图层无任何展示位，`required_protection`（影响范围）字段从未消费 | 类型已定义，前端零引用 |
| 4 | 候选提示词概念缺失：前后端均无 `candidates`，「当前候选提示词编号」「候选切换」无法满足 | `EnhancementResult` 只有单一 `primary_prompt` |
| 5 | 一键接受全部 / 一键拒绝全部缺失 | 仅逐项操作 |
| 6 | 澄清无「剩余轮次」明确文案（仅「N/3 轮」隐含） | 澄清条标题 |
| 7 | `Suggestion.kind` 在 UI 直接输出英文枚举原文，无中文映射 | 建议卡片小徽标 |
| 8 | 「可选补充 5 项」标题硬编码，0.3.0 起建议为 0-5 条动态 | 标题写死 `<b>5 项</b>` |

## 3. 总体实施原则

- 保持现有 `EnhancementResult` 字段兼容：不删除、不改名、不改语义任何旧字段；新增字段全部可选。
- 不改最小干预原则与系统提示词 v2.1.0 的既有行为要求；v2.2.0 只做增量（§6.1）。
- partial/fallback 既有降级行为不得回退：主提示词有效即可交付的规则不变，新字段缺失不参与降级判定。
- 不做无关重构；EnhanceView 保持「展示组件 + App 持有状态」的现有结构，新逻辑优先放进 `lib.ts` 纯函数。
- 涉及系统提示词的改动放在实施第二批（§8），与纯前端改动分离。

## 4. v0.3.3 详细需求

### 4.1 结果区域必须显示（8 项）

1. **增强等级**：已实现。等级为 `none` 时按 §4.6 第一条追加引导。
2. **交付状态**（新增）：结果面板头部显示交付状态徽标——`complete` =「完整交付」（绿）、`partial` =「部分交付」（黄）、`fallback` =「原文回退」（灰）。字段缺失时按 `complete` 处理（沿用现有归一化兜底）。`fallback` 仍同时保留现有「已保留原文」notice，两者并存。
3. **原文和结果字数变化**：已实现，保持「原文 X 字 → 结果 Y 字（N 倍）」格式。
4. **修改摘要**：已实现，保持按 changes 类型去重推导，无修改显示「无实质修改」。
5. **用户原始事实**（新增）：独立区块展示 `facts` 列表，逐条为用户输入中的原始事实。`facts` 为空或缺失时显示「未从输入中提取到明确事实」。不得与「模型假设」混排，两个区块必须视觉分离——事实是用户提供的，假设是模型推测的。
6. **模型假设**：已实现，保持。
7. **风险提示及影响范围**（新增）：`risk_flags` 非空时显示风险卡片列表，每条包含：类别（中文映射）、说明（description）、影响范围（`required_protection`，前缀「需要保护：」）。类别中文映射至少覆盖后端已有类别；`risk_flags` 为空时不显示该区块。
8. **当前候选提示词编号**（新增）：结果面板显示「候选 X/N」。多候选时提供切换器（§4.2）；单候选显示「候选 1/1」。

### 4.2 必须提供的操作（10 项）

已实现 7 项（逐项接受、逐项拒绝、恢复原文、仅保留必要修改、手动编辑、撤销/重做、重新生成），保持现状。新增 3 项：

- **一键接受全部**：依次应用全部 `pending` 状态的修改；某项锚点未命中时跳过该项并追加非阻塞 notice「原文已被编辑，无法自动应用该项」，不中断其余项；完成后输出为重建结果，整体进撤销栈。
- **一键拒绝全部**：把全部 `pending` 项置为 `rejected`。不回退已 `accepted` 的项——已接受项的回退继续由「仅保留必要修改」承担，两个操作语义不得重叠。
- **候选提示词切换**：多候选时在「候选 X/N」处提供切换（按钮组或下拉）。切换行为：用候选文本替换当前输出（走现有 commitOutput 路径，自动进撤销栈、可撤销）；不修改原文输入；流式生成中禁用。候选只切换文本，不携带对 changes/suggestions 的改动。

### 4.3 Suggestion.kind 五类标记

- 建议卡片徽标显示中文映射：`goal`=目标、`context`=背景、`format`=格式、`constraint`=约束、`alternate_intent`=备选意图。
- 未知枚举值原样显示，不得因未知值崩溃。
- 点击建议卡片弹出详情、应用后显示「已加入」并禁用——现有行为保持。

### 4.4 partial 与 fallback 状态

现有六项（非阻塞提示、保留原始输入、保留复制、不清空附件、不阻止手动编辑、字段级缺失 notice）保持，全部不得回退。新增一项：

- **缺失字段清单化告知**：`delivery_status = partial` 时，在 notices 区块顶部聚合显示一行缺失字段清单，如「本次交付缺失：假设、建议」，由前端根据结果中为空的附属字段（assumptions / changes / suggestions / risk_flags / facts / candidates）推导；全部齐备时不显示。不改变后端既有逐字段 notice，两者并存。

### 4.5 三轮澄清

- 澄清条标题显示「当前第 X/3 轮 · 剩余 Y 轮」（X 从 1 起，Y = 3 − X）。
- 既有行为保持：留空跳过本轮、跳过时上下文记「用户选择跳过本轮。」、结束澄清保留临时结果、临时结果基于 assumptions 且界面可见。
- 不得在本地虚构数字、事件或事实：澄清与候选、事实展示一律只使用模型返回或用户输入的内容。

### 4.6 基于 v0.3.2 评测发现的体验修正（新增）

依据 `docs/PromptCraft-v0.3.2-评测报告.md`：

1. **none 等级引导保留原文**：`enhancement_level = none` 时，在结果面板头部（交付状态徽标旁）显示非阻塞引导「增强器判断无需修改，建议直接使用原文」。不弹窗、不阻断复制与编辑。
2. **过长结果精简提示**：结果字符数超过原文字符数 3 倍时，追加一条非阻塞 notice「结果明显长于原文，可尝试『仅保留必要修改』精简。」同一次结果只提示一次，不重复、不阻断任何操作。

## 5. 字段与兼容性

### 5.1 新增字段

```typescript
// src/types.ts 新增
export interface PromptCandidate {
  index: number;      // 从 1 起
  text: string;
  note?: string;      // 一句话说明该候选的取向，可缺省
}

export interface EnhancementResult {
  // ……全部旧字段保持不变……
  facts?: string[];
  candidates?: PromptCandidate[];
}
```

### 5.2 约束

- 第 1 个候选 `index = 1` 且 `text === primary_prompt`；后端归一化负责保证，前端不做二次校验。
- `candidates` 缺失或为空 → 前端按单候选（`primary_prompt`）处理，显示「候选 1/1」。
- `fallback` 交付 → 候选仅有原文一项。
- `facts` 缺失 → 按空数组处理，显示「未从输入中提取到明确事实」。
- `src/schemas.ts` 的 zod schema 同步增量字段，均带缺省值（沿用现有 default 兜底风格）。
- `normalizeResult`（`src/lib.ts`）为两个新字段加兜底，旧历史记录 / 旧模型输出打开不报错。

## 6. 关键技术决策

### 6.1 facts 由后端提取

前端无法可靠地从自由文本中「提取用户原始事实」，该能力放在后端系统提示词：

- `src-tauri/src/prompts.rs` 系统提示词 v2.1.0 → **v2.2.0**，增量要求：输出 JSON 新增 `facts` 数组，逐条为用户原文/上下文中**逐字或近逐字**的事实要点；只允许来自用户输入，不得改写、不得推断、不得虚构；没有明确事实时输出空数组。
- `models.rs` 增加 `facts` 字段；`provider.rs` 归一化缺省空数组；`facts` 缺失不影响 `delivery_status`（沿用 0.2.1「主提示词有效即可交付」原则）。

### 6.2 candidates 由后端产出

- 系统提示词 v2.2.0 同时要求：`enhancement_level` 为 `light` / `clarify` 时输出 1-3 个候选，第 1 个即 `primary_prompt`，`note` 用一句话说明该候选取向（如「更简洁」「更强调约束」）；`none` 等级不输出候选。
- 解析失败或缺失时按无候选处理，不触发结构修复重试、不影响交付状态。
- 候选与 changes/suggestions 解耦：切换候选不改动任何修改项状态。

### 6.3 批量操作与候选切换的实现路径

- 批量接受：循环现有 `applyChangeDecisionSafe`，全部完成后一次性 commitOutput，避免多次压撤销栈。
- 批量拒绝：仅更新 changes 状态，不改输出文本。
- 候选切换：调用现有 commitOutput（快照进撤销栈），切回原候选同样可撤销。

## 8. 实施顺序与不做清单

### 8.1 实施顺序（三批，批内可并行）

1. **第一批（纯前端，无行为回归）**：交付状态徽标、风险卡片与影响范围、kind 中文映射、候选编号占位、「5 项」动态化、批量接受/拒绝、澄清剩余轮次文案、§4.6 两个修正、缺失字段清单化。
2. **第二批（后端）**：系统提示词 v2.2.0（facts + candidates）、models/provider 归一化与校验、同轮更新 `evaluation/test_enhancer.py`。
3. **第三批（前端接线）**：facts 区块、候选切换器接入 commitOutput、zod/normalizeResult 兜底、旧数据兼容验证。
4. 收尾：CHANGELOG、README、版本号四处、（测试与验收方案暂缓，如后续补测再另立文档）。

### 8.2 当前明确不优先开发

- 重新设计整体视觉风格、装饰性界面改动。
- 候选数量超过 3、候选自动评分或排序。
- 修改接受率的统计上报、任何遥测。
- 澄清轮数超过 3、自动回答澄清。
- 云端账号、同步、自动操作目标模型网页。
- OCR、Excel、PPT、项目文件夹解析。

### 8.3 备注

- 测试与验收方案本轮暂缓制定；实施完成后至少保证既有测试套件（`npm.cmd test`、`python -m pytest evaluation -q`、`cargo fmt/test/clippy`）不因本版变更而失败。
- `prompts.rs` 变更会改变模型输出行为，若后续恢复效果评测，需重跑 `samples_regression.yaml` 回归确认回退率未上升。
