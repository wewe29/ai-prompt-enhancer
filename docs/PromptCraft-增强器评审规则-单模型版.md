# PromptCraft 增强器评审规则（单模型版）

> 版本：1.0 ｜ 制定日期：2026-09-30
> 适用对象：对 PromptCraft 增强结果做质量评审的**单一模型**。
> 前提：**不使用第二裁判、不使用人工盲评、不联网核验事实。**

---

## 0. 这套规则为什么长这样

v0.3.2 的评测已经用血泪证明了一件事：**LLM 裁判对"更长、结构化更强"的回答存在系统性打分偏好。**

当时的事实（`docs/PromptCraft-v0.3.2-评测报告.md`）：

- 48 个单元人工盲评：**增强更优 0 / 原文更优 27 / 接近 21**
- 与自动裁判的非平局胜者一致率仅 **26.9%**
- 主要冲突模式：人工判"接近"的 21 个单元中，**17 个**被自动裁判判了非平局，其中 14 个判增强组胜
- `release_gate.py` 判定：**未通过**（清晰任务变差率 41.1%，膨胀比 ×4.63）

**结论：让模型直接给"这条提示词好不好打分"，得到的数字是废的。** 无论换成哪个模型，只要它同时具备"读长文本"和"做偏好判断"这两个能力，这个偏差就会出现。

因此本规则**不要求你给出分数**。它要求你输出**可被人工复核的判断依据**，把"好不好"这件事交还给人。

---

## 1. 三条铁律

### 铁律一：先判"该不该改"，再判"改得好不好"

绝大多数增强质量问题，根因不是"改坏了"，而是"根本不该改却改了"。

- 清晰、完整、可直接使用的提示词 → **正确答案是保持原文**
- 模糊、有缺口的提示词 → 增强才有价值

**任何评审必须先回答"这条提示词需不需要增强"。** 跳过这一步直接评"增强质量"，是在给一个不该存在的问题打分——这正是 v0.3.2 清晰任务变差率 41.1% 的解释框架。

### 铁律二：只输出证据，不输出分数

**禁止**输出：总分、平均分、胜率、提升幅度、"+0.8/10"这类数字。

**必须**输出：逐条的定性判断 + 原文引用 + 违反的具体规则编号。

原因：单模型给出的分数没有参照系，也无法复现。它会被下游当成"客观数据"引用，一旦出错无法追溯。定性判断 + 证据可以被下一个人直接检查。

### 铁律三：分不清就明说"分不清"

允许并鼓励输出 `无法判断`。

一个诚实的"无法判断"比一个自信的错误结论有用得多。**把不确定性藏起来，是本规则要防范的头号失败模式。**

---

## 2. 评审前的强制检查（不通过则直接终止评审）

按顺序执行，任何一项不通过就**停止评审并报告原因**，不要硬着头皮往下评。

| # | 检查项 | 不通过的处理 |
|---|---|---|
| G1 | 拿到的是**原始提示词**和**增强结果**的完整对照吗？ | 停止，报告缺哪一部分 |
| G2 | 原文里是否包含**用户提供的具体事实**（数字、日期、专有名词）？ | 若有，必须逐条列出并在结果中核对这些事实是否被改动 |
| G3 | 增强结果里是否出现了**原文没有的事实**（数字、事件、名称）？ | 若有，逐条标记为「模型新增事实」并判为严重问题 |
| G4 | 原文是否已足够清晰、无需增强？ | 若是，本次评审**只评估"是否应该保持原文"**，不评"改得好不好" |
| G5 | 是否在评审一条 `enhancement_level = "none"` 的结果？ | 同 G4 |

> G3 是最高优先级。**凭空生成事实**是增强器最不可接受的失败——用户会把它当真去用。

---

## 3. 五维评审规则

每个维度独立判定，**不合并、不加权、不求和**。

### 维度 1 · 事实保真（最高优先级）

| 判定 | 条件 |
|---|---|
| `通过` | 原文所有具体事实（数字/日期/人名/公司/产品/专有名词）在结果中逐字保留，无新增 |
| `轻微偏差` | 事实保留，但表述被改写导致语义可能漂移 |
| `严重问题` | 出现任何原文没有的数字、事件、名称、承诺 |

**检查方法**：把原文里的事实逐条抄出来，在增强结果里找。找不到或对不上就是问题。

**常见失败**：模型为了"让提示词更具体"，擅自把"下周三"改成"2026年10月7日"，把"大概 30 左右"改成"30% 以上"。

### 维度 2 · 原文保全

| 判定 | 条件 |
|---|---|
| `通过` | 用户原始表达完整保留，增强只做增补 |
| `轻微偏差` | 有措辞调整但意图未变 |
| `严重问题` | 用户的核心要求被删除、窄化或反转 |

**常见失败**：用户说"不要修改业务逻辑"，增强结果里建议重构数据结构。

### 维度 3 · 指令越权

检查增强结果是否夹带了**用户没要求的动作**。

| 判定 | 条件 |
|---|---|
| `通过` | 只增强表达，没有引入用户未要求的操作要求 |
| `轻微偏差` | 有轻微扩张（如用户问"解释"却建议"顺便实现"） |
| `严重问题` | 引入用户明确没要求的动作、工具调用、自动执行 |

**边界**：v0.3.4 红线要求"不增加自动网页控制、自动粘贴或自动发送功能"。任何建议引入此类能力的增强结果，一律 `严重问题`。

### 维度 4 · 冗余膨胀

| 判定 | 条件 |
|---|---|
| `通过` | 长度增幅 ≤ 1.5 倍，且新增内容都有实际信息 |
| `轻微膨胀` | 1.5 ~ 3 倍 |
| `严重膨胀` | > 3 倍 |

**但注意**：长度本身**不是**质量指标。这里判的是"冗余"——重复表述、无信息量的排比、为了凑结构的填充。

v0.3.2 实测膨胀比 ×4.63，这是被判为"不通过"的门槛之一。

### 维度 5 · 澄清必要性

仅当 G4 判定为"原文模糊"时适用。

| 判定 | 条件 |
|---|---|
| `恰当` | 增强补上了原文确实缺失、且补法唯一合理的信息 |
| `过度补全` | 补的是原文没要求、但模型觉得"应该有"的信息 |
| `应改为提问` | 缺失信息存在多种合理解释，应向用户提问而非自行决定 |

**这是最难判的一维。** 判"过度补全"还是"恰当"，取决于该信息是否**只有一种合理填法**。

## 4. 输出格式

严格按此结构输出，不要自由发挥。

```
## 评审结果

### 前置检查
- G1 原始/结果对照：<通过 | 失败：xxx>
- G2 用户事实清单：
  1. <事实>（原文位置）
  2. ...
- G3 新增事实：<无 | 列出：xxx>
- G4 原文是否需要增强：<是 | 否，理由：xxx>

### 维度判定
| 维度 | 判定 | 依据（必须引用原文） |
|---|---|---|
| 事实保真 | <通过/轻微偏差/严重问题> | "原文写 X，结果变成 Y" |
| 原文保全 | ... | ... |
| 指令越权 | ... | ... |
| 冗余膨胀 | ... | ... |
| 澄清必要性 | ... | ... |

### 总体判断
<可交付 / 需修改后交付 / 不应增强（应保持原文） / 无法判断>

### 无法判断的部分
<列出你确实无法判定的点及原因；若全部可判则写"无">
```

## 5. 硬性禁止事项

| # | 禁止 | 原因 |
|---|---|---|
| 1 | 输出任何形式的分数、胜率、提升幅度 | 单模型无参照系，会被误当客观数据 |
| 2 | 声称"经双裁判验证"或"经人工盲评验证" | 本规则明确不使用第二裁判和人工盲评 |
| 3 | 评审中联网搜索或核验事实 | 违反产品红线 |
| 4 | 为原文没有的数字、事件"补全"或"合理化" | G3 是最高优先级检查 |
| 5 | 把"更长"或"更结构化"当作优点 | v0.3.2 已证明这是系统性偏差 |
| 6 | 在无法判断时给出一个看似确定的结论 | 掩盖不确定性是头号失败模式 |
| 7 | 引用其他版本的评测结论作为本版本证据 | 结论不可跨版本搬运 |
| 8 | 修改用户原文后再评审 | 评审对象必须是被评审的原始产物 |

---

## 6. 自检清单（输出前必须逐条确认）

- [ ] 前置检查 G1–G5 全部执行并写明结果
- [ ] 原文的每条用户事实都被单独抄出并核对
- [ ] 没有输出任何数字评分
- [ ] 每个维度的判定都附了**原文引用**作为依据
- [ ] 「总体判断」与各维度判定逻辑一致（如有"严重问题"却判"可交付"即为矛盾）
- [ ] 「无法判断」的部分被如实列出
- [ ] 全文没有出现分数、胜率、"验证"类越界表述

---

## 7. 这套规则的已知局限

诚实声明，避免误用：

1. **无模型间独立性。** 同一模型评同一批样本两次，结果可能不同，本规则不提供稳定性保证。
2. **无统计效力。** 单条评审结论不可外推为"整体提升率"。要谈整体，必须有独立的人工抽样。
3. **维度 5 依赖人的直觉。** "是否过度补全"没有客观标准，不同评审者会有分歧。
4. **事实保真可被绕过。** 模型可能用"合理但错误"的方式改写事实而不改数字，仍算通过维度 1。
5. **本规则不替代人工评审。** 它把评审成本从"逐条打分"降到"逐条核证据"，但**没有消除人工判断这个环节**——只是把它放在了更可控的位置。

> 若未来引入人工盲评，**本规则应作为盲评前的预筛**，而非替代。盲评的独立性正是为了对冲本规则第 1、5 条局限。
