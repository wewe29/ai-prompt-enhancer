1. **【已实测】v0.4.0 两份报告依赖的原始数据在本机已不存在，结论不可复现。**

2. **【已实测】盲评揭盲存在标签大小写反转 bug，它使「人工零胜」这一核心结论失效。**
   `evaluation/v032_blind_review.py:153-157` 把人工答案 `.lower()` 成 `"a"/"b"`，
   却与 `enhanced_label` 的 `"A"/"B"` 直接比较 → `"a" == "A"` 恒为 False

3. **【已实测】修正映射后，人工结论是「4 胜 / 4 负 / 8 平」而不是「0 胜 / 8 负 / 8 平」。**
   人工与自动裁判的一致性：非平局口径 **26.9% → 53.8%**，全量 22.9% → 37.5%，
   Cohen's κ 0.079 → 0.152，`direction_consistent` **False → True**。
   ⇒ v0.3.2 报告 §5.2 的表与 v0.4.0 效果验证报告 §2.2 的「clear 档人工零胜」整条论证链，
   建立在一个被反转的字段上。

4. **【我的推断】「双峰」是**未被排除**的假设，不是**被数据证实**的假设；
   而「n=3 也救不了」这一步是超出证据的。**
   我构造的零模型（每样本固定倾向 Beta 异质性 + 采样误差率 e=0.140）**同时复现了全部三项观测**：
   翻转率 0.472（实测 0.450）、点击内分歧 0.241（实测 0.300）、内部全一致的翻转样本 2.31 条（实测 2）。
   反向检验：按 30% 分歧率反解 e=0.184 时，观测到 ≤2 条的概率 **0.635** ⇒ 完全不异常。
   更关键：**锐双峰模型（e=0）被同一次实验的 30% 点击内分歧率直接反驳**，
   而「n=3 救不了」的推理恰恰依赖「峰是尖的」这个前提。
   ⇒ n=3 仍值得一次 60 次调用的定向实验（见 §1.5）。

5. **【已实测】「温度 0.35→0.1 把 clear 翻转率从 55% 降到 30%」不成立。**
   该结论写进了 `docs/PromptCraft-v0.4.0-iteration-spec.md` §1、§5.1，并被
   `src-tauri/src/provider.rs:390-394` 引为唯一「被数据证明有效」的改动。
   但：(a) 55%→30% 的 z 检验只有 **1.65 个标准误**，不是规格声称的 2.5；
   (b) 同配置的两次独立运行给出 **30% 与 71%**，效应量（25 点）**小于**观测到的运行间差（41 点）；
   (c) 报告只取了两次运行中较好的那一次作为「结果」，无偏估计应是均值 50.5%；
   (d) 30% 同时是「翻转率」和「分歧率」两个不同量的取值，存在口径混用。

6. **【已实测】规格 §7 的门槛 1/2/3 的间距全部小于噪声地板，属不可判定的门槛。**
   噪声地板 41 个百分点（两次同配置运行之差）vs
   门槛 1 间距 25 点、门槛 2 间距 3 点、门槛 3 间距 10 点。
   尤其 **门槛 1 的目标值 ≤30% 恰好等于「两次运行中较好的一次」** ⇒ 该门槛重跑时约等于掷硬币。

7. **【已实测】区分 20% 与 40% 翻转率需要 n≈62/组（两独立组）或 n≈70（配对 + McNemar），
   但前提是「两臂在同一轮内交错执行」；跨运行比较则加样本数无效。**
   详见 §3。

## 一、为什么改判据和投票都失败

### 1.1 先把「双峰」这个发现拆成三层

投票实测报告 §三 的原始陈述是：**12 个翻转样本里有 2 个**
（`translate_product_manual`、`creative_story_opening`）
**每一次点击内部两次采样完全一致、三次点击之间却跳了**。

这一句话里其实混了三个强度完全不同的命题：

| # | 命题 | 证据强度 |
|---|---|---|
| P1 | 这 2 条提示词的档位分布在两个峰上 | **【他人实测】** n=2，报告自述「不是普适结论」（§六.3） |
| P2 | 这 2 条提示词的峰是**尖的**（点击内必然落同一峰） | **【我的推断】被同一次实验反驳**，见下 |
| P3 | 因此任何点击内投票都治不了，n=3 也不行 | **【我的推断】超出证据** |

**P2 为什么不成立**【已实测】：同一次实验测得 clear 档**点击内两次采样分歧率 30%（18/60 次点击）**
（投票实测报告 §一、§四）。若分布真是「双峰且峰尖」，点击内两次采样应几乎完全一致（分歧率趋近 0）。
**30% 的分歧率与「尖峰」不相容。**

**P1 是否必要**【我的推断】：我构造了一个**不含双峰**的零模型：

> 每条提示词有一个固定的档位倾向 `p_i`（异质性来源）
> 每次点击抽该点击的档位 `mode ~ Bernoulli(p_i)`，两次采样各自以 `1-e` 的概率等于 `mode`
> 报告层取第一次采样（与实现的破平局规则一致）

用 `Beta(0.5, 3.0)` 的异质性 + `e = 0.140` 拟合后：

| 观测量 | 实测 | 零模型预测 |
|---|---|---|
| 跨点击翻转率 | 0.450（9/20） | **0.472** |
| 点击内 2 采样分歧率 | 0.300（18/60） | **0.241** |
| 翻转样本中「内部全一致」的条数 | **2** / 9 | **2.31** |

**三项全部复现，不需要「双峰」这个额外假设。**
反向检验：按实测 30% 分歧率反解 `e = 0.184`，模型期望内部全一致 2.15 条，
观测到 ≤2 条的概率 **P = 0.635** ⇒ 观测到的「2」完全不异常。
反之，锐双峰模型（e=0）期望 6.92 条，观测 ≤2 条的概率 0.031 ⇒ **锐双峰模型反而不被数据支持**。

> **结论**：现有数据既没有证实「双峰」，也没有排除它；
> 但它**已经排除**了「峰是尖的」，而「n=3 也救不了」恰恰只依赖后者。

### 1.2 「n=3 救不了」这个推论值多少钱

`【我的推断】` 它的价值取决于 `e`（点击内采样误差率），而 `e` 是可以从已有数据估出来的量：

| 模型 | n=2 的用户可见跨点击翻转率 | 改 n=3 多数投票后 | 变化 |
|---|---|---|---|
| 有误差率模型（e=0.184） | 0.606 | **0.505** | **−10.0 个百分点** |
| 锐双峰模型（e=0） | 0.389 | 0.388 | −0.1 个百分点 |

`【我的建议】` **不要在 n=3 上继续靠推理。** 一次 20 样本 × 3 次点击 × 每次 3 采样
= 180 次调用（按规格 §7 的成本表约 $0.39，35 分钟）就能把 `e` 直接测出来，
并同时给出 n=3 多数投票的真实收益。
这是当前**性价比最高的一个实验**，而且它直接决定 §2 的推荐路径要不要改。

### 1.3 改判据为什么必然失败（把两条失败经验讲成一般结论）

**v2.3.0（none 判定清单 4 条）**【他人实测，规格 §5.1 表】：clear 翻转率 0%、medium 10%，
**light 出现率 clear/medium = 0%/0%**。

机制【我的推断】：none 判定清单的 4 条命中条件，本质是「**这条提示词写清楚了**」的 4 种说法。
而在 clear 档，「写清楚了」是**定义上**成立的 ⇒ 4 条任一命中 = 必然命中 ⇒ 全部判 none ⇒ 功能死。
翻转率 0% 与 light 出现率 0% 同时出现，**正是「判据恒真」的指纹，不是「判得更准」的证据**。

**v2.4.0（light 正向条件 + 3 正例 2 反例）**【他人实测，规格 §5.1 表】：clear 45%、**medium 50%**，
比基线（medium 33%，效果验证报告 §3.2）更差。

机制【我的推断】：正向条件是在**样本空间里**用 5 个例子定义边界，
而 clear/light 的真实分界是语义判断，不是可枚举的模式。
更关键的是它**删掉了 1.5× 膨胀上限**（规格 §5.2 已作废）⇒ 判据变松 ⇒ 翻转率上升。

> **一般结论**【我的推断】：
> 改判据之所以两次都失败，是因为它试图把一个**连续量**（这条提示词值不值得动）
> 变成**离散判定**，而这个连续量的可判边界**不存在客观标准**。
> 规格 §5.1 自己给出了根因：「这条信息缺了，目标模型是*给不出东西*，还是*给得出但不够好*？」——
> 后者不是客观事实。
> `clarify` 之所以稳（20/20 三次全稳，规格 §2.2），是因为它的触发条件是**客观**的（缺少指称对象）。
>
> **推论**：任何**继续在 none/light 之间找判据**的方案（第三条路是例外，见 §2）
> 都是在给一个不存在的边界做拟合。应当停止这条路。

### 1.4 温度这条路到底赚了多少（推翻「2.5 个标准误」）

`【已实测】` 复核 `docs/PromptCraft-v0.4.0-iteration-spec.md` §1/§5.1 与
`docs/PromptCraft-v0.4.0-效果验证报告.md` §3.2/§5.1/§5.2：

| 主张 | 出处 | 我的复核 |
|---|---|---|
| clear 翻转率 55%（temp 0.35） | 效果验证报告 §3.2，11/20 | 成立 |
| clear 翻转率降到 30%（temp 0.1） | 效果验证报告 §5.1 | **取自两次运行中较好的一次** |
| 同配置两次独立运行 = 30% 与 71% | 效果验证报告 §5.2、规格 §10.2 | 成立，**噪声地板 41 点** |
| 「约 2.5 个标准误」 | 规格 §1、§5.1 | **实际 1.65 个标准误**（n=20/组，z 检验） |
| light 出现率 52% → 57% | `provider.rs:392` | **两个数字在任何留存文档中都不存在** |

**四个独立的问题**：

1. **选择性报告**：同一配置跑了两次（30%、71%），报告把 30% 当「本轮结果」，
   把 71% 降级到「诚实边界」当噪声。无偏估计是均值 **50.5%**。
2. **效应量 < 噪声**：宣称改善 25 点，而同配置两次运行能差 41 点。
3. **算术错误**：1.65 个标准误被写成 2.5。以 2.5 SE 反推，p ≈ 0.012；
   以真实的 1.65 SE 反推，双侧 p ≈ 0.10 ⇒ **不显著**。
4. **口径混用**：30% 同时是「翻转率（20 样本）」和「逐次调用分歧率（60 次点击）」的取值。
   §5.1 的「从 55% 降到 30%」把**翻转率**和**分歧率**放在一句里比较。

`【已实测】` 另外，`src-tauri/src/provider.rs:390-394` 的注释
引用 `docs/PromptCraft-v0.4.0-效果验证报告.md` 作为依据，
而**该文档全文 0 次出现「温度」「temperature」「temp」「0.35」**（`grep` 核对）
⇒ 代码注释指向的证据在它引用的文件里不存在。

> **【我的建议】** 温度 0.1 本身**无害**（light 出现率没有塌陷，规格 §5.1 显示 57%），
> 保留 0.1 是合理的。但**不要**在发布说明、代码注释或下一版规格里
> 把它写成「被数据证明有效的改动」。它当前的状态是：
> **一次 41 个百分点噪声下的单点观测，方向未知。**

### 1.5 顺带：n=2 投票的失败是数学恒等式，不是实现 bug

【他人实测，投票实测报告 §二】`majority_vote([A,B]) ≡ A`，因为 2 个样本不存在多数，
任意 A≠B 都是 1:1 平局，按首次出现破平局必然取 A。117/117 次投票改过结果的次数为 0。
这一条**没有问题**，报告的推导和实测一致。它被正确地记成了「结构性必然」而非实验观察。
⇒ 真正的教训不是「投票没用」，而是**「n=2 投票」这个概念本身不成立**，
所以它从未被真正测试过。§1.2 的 n=3 才是第一次有效测试。

## 二、「把档位决策从 LLM 手里拿走」的三条子路

统一评价框架：对**用户可见的稳定性**（同一提示词两次点击结果一致）是否有帮助，
而不是对「模型更准」有帮助。

### 2.1 (a) 规则化判定

**做法**：用可计算的启发式特征决定档位，例如：原文长度、是否包含可识别的目标/格式/约束关键词、
是否存在指称对象缺失。命中 → none / clarify；否则 → light。

| 维度 | 评估 |
|---|---|
| **可实现性**【我的推断】 | **高**。纯前端/Rust 侧可做，无额外 API 成本，无延迟增量（当前 `provider.rs` 已在同一次响应里返回 `enhancement_level`）。 |
| **主要风险** | ① **档位塌陷**（v2.3.0 的教训）：规则太严 → 全判 none → 增强器不干活。必须用规格 §5.3 的**双指标联立**（翻转率 + light 出现率）兜底。<br>② **规则与语义脱节**：长度、关键词都是代理量（proxy），不是「值不值得动」本身 ⇒ 代理量与目标的相关性有多高，决定上限有多低。<br>③ **维护成本**：规则会与内容漂移。 |
| **验证方法** | **离线即可**，不需要 API：<br>(1) 用 `docs/evaluation-data-v032/blind_answers.json` 的 48 条人工判断 + `blind_key.json` 的 `sample_id`/`difficulty`，直接算规则能复现多少人工结论（当前上限：48 条里人工只有 10 条选增强、21 条平局 ⇒ **规则能对齐的上限本就有限**）。<br>(2) 用 `samples_v30.yaml` 的 `expected_behavior` 60 条算「恰当率」。<br>(3) **成本 = 0**。这是三条路里唯一能离线全量验证的。 |
| **我的判断** | 值得做，但**只能解决 `none` vs `light` 的边界**，`clarify` 不该动（规格 §2.2：clarify 判据是资产）。而且它**必然是粗糙的**——因为边界本身不存在客观标准（§1.3）。 |

### 2.2 (b) 前置轻量分类器

**做法**：先用一次便宜的小模型/嵌入/启发式打分做二分类（要不要动），只有判定「要动」才调用完整增强。

| 维度 | 评估 |
|---|---|
| **可实现性** | **中**。需要一个额外模型调用或本地分类器；当前 `provider.rs` 是单次结构化输出（`response_format: json_object`），改成两段式会**增加延迟与成本**。 |
| **主要风险** | ① **分类器自己也在漂移**——漂移只是被推迟，没有消除；必须先证明分类器比现在的端到端判定**更稳**，否则只是多了一个不稳定环节。<br>② **两次调用之间的一致性**：分类器判「要动」但增强器判「不适用」，用户看到空结果。 |
| **验证方法** | 关键问题：**分类器自身的跨调用一致率是多少**？<br>用与投票实测报告 §四 相同的「逐次调用分歧率」指标（分母是点击数 60/57，不是样本数 20/19），在**同一个提示词上连发 3 次分类器**，测它的分歧率。<br>判定标准【我的建议】：**分类器的分歧率必须显著低于当前端到端的 30%**，否则这条路不成立。成本：20 样本 × 3 = 60 次轻量调用。 |
| **我的判断** | 这是三条路里**最可能真正解决漂移**的一条（因为分类器的输出空间小、判据单一），但也是成本最高、最需要先验证「它自己稳不稳」的一条。**必须先做那个分歧率实验，再决定是否投入。** |

### 2.3 (c) 让用户在两个结果里选

**做法**：不猜档位。生成两个候选（原文 vs 增强，或两个增强变体），让用户选。

| 维度 | 评估 |
|---|---|
| **可实现性** | **最高**。不需要新模型能力，只需要 UI 改一处（`src/components/SuggestionModal.tsx` 已有交互骨架）。 |
| **主要风险** | ① **把决策成本转嫁给用户**——这是本产品的核心价值主张（「一键增强」），改掉等于改产品定位。<br>② **但它有一个被忽视的优点**：它把「不可判的边界」变成「用户可判的边界」，**从根本上消除了模型假装能判的问题**。<br>③ 需要仔细设计默认态：不能变成「每次都要用户选」。 |
| **验证方法** | **不需要 API 也能做一半**：先做**可判性研究**（不测用户偏好，测「用户能不能判」）。<br>用 `docs/evaluation-data-v032/` 的 48 条人类判断，检验：<br>当人工选了 A/B（27 条非平局）时，人类在 0-10 四维打分上的**判别力**有多强（能否区分 A 更好 vs B 更好）。<br>如果连给出两份答案的评审者都经常选不出来（人类平局率 21/48 = 43.8%），那让用户二选一只是把 43.8% 的困惑直接摊到界面上 ⇒ **该方案的前提不成立**。 |
| **我的判断** | **作为 fallback 值得做，作为主方案不做。** 但 §4.1 的发现让它的地位上升了：既然 none/light 的边界客观上不可判，**把选择权交还用户是唯一不撒谎的做法**。 |

### 2.4 推荐

`【我的建议】` **三路并行，但顺序和目的不同**：

1. **先做零成本的诊断**（30 分钟，0 次 API 调用）：
   用 §1.2 的方案测出点击内误差率 `e`，同时用 §2.1 的离线方法测规则能对齐多少人工判断。
   这两个数决定后面怎么走。
2. **主线：前置分类器 (b)**，但**先只做分歧率实验**（60 次轻量调用），不投入实现。
   判定线：分类器跨调用分歧率 **< 10%** 才继续。
3. **兜底：用户二选一 (c)** 作为 `clarify` 之外的显式出口
   （例如「这两个版本你更想要哪个？」），不改变默认一键路径。
4. **规则化 (a) 只用在 `clarify` 的触发前置**（缺指称对象这类客观条件），
   不用在 `none`/`light` 边界上——那是在拟合不存在的边界。
5. **不要再碰 none/light 判据**（§1.3）。

`【我的推断】` 还有一个**不在这三条里但更根本**的选项，值得 Chief 考虑：
**把 `enhancement_level` 从产品承诺降级为内部实现细节。**
现在的产品形态是「我替你决定该不该动」，而这件事客观不可判。
如果改成「我给你一个增强版，你觉得不需要就用原文」（即把 `none` 变成默认路径之一而非唯一正确路径），
那么**档位漂移就不再是缺陷，而是可有可无的内部变量**。
这比三条路都更彻底，但它是产品决策，不是测量决策。

## 三、统计功效足够的实验设计

### 3.1 目标量与效应量

**主指标（用户可见的稳定性）**：

> **跨点击翻转率** = 在 3 次独立点击中，3 次给出的 `enhancement_level` 不全相同的提示词占比
> 分母 = 提示词条数（不是点击数）

**辅指标**：
- 逐次调用分歧率 = 单次点击内两次独立采样给出不同档位的比例（分母 = 点击数）
- light 出现率（规格 §5.3 的红线，防止用「什么都不做」换稳定）
- 长度比（膨胀比）分布

`【我的建议】` **同时报告分母和分子**。当前最大的报告缺陷之一是分母会静默收缩（§4.2 A-2/A-4）。

### 3.2 两独立组（最保守：两臂用不同提示词集）

单侧 α=0.05，power=0.80，两比例 z 检验：

```
n/组 = (z_{1-α} + z_{1-β})² · [p₁(1-p₁) + p₂(1-p₂)] / (p₂-p₁)²
      = (1.645 + 0.842)² · [0.20×0.80 + 0.40×0.60] / 0.20²
      = 6.185 · 0.40 / 0.04
      = 61.9  →  62/组
```

| 效应 | n/组（单侧） | n/组（双侧） |
|---|---|---|
| 20% → 40% | **62** | 79 |
| 20% → 30% | 229 | 291 |
| 30% → 55% | 46 | 58 |

功效曲线（20% vs 40%）：n=20 → 0.41；n=40 → 0.64；n=62 → 0.80；n=79 → 0.88；n=120 → 0.97。

### 3.3 配对设计（同一批提示词，两臂交错执行）—— 推荐

McNemar 检验只看不一致对。记 `y = P(A翻,B不翻)`、`z = P(A不翻,B翻)`、`x = P(都翻)`：
`y + x = p₁`，`z + x = p₂` ⇒ `z - y = p₂ - p₁ = Δ`；`y + z = disc`（不一致对比例）。

H0 下每个不一致对以 1/2 概率贡献 ±1 ⇒ `Var[z−y] = disc·n`
⇒ 统计量 `= Δ·√(n/disc)`，所需 `n = disc·(z_{1-α}+z_{1-β})²/Δ²`

| 不一致对比例 disc | n（单侧，Δ=20 点） | n（双侧） |
|---|---|---|
| 0.30 | 47 | 59 |
| 0.45 | **70** | 89 |
| 0.60 | 93 | 118 |

功效曲线（Δ=20 点，disc=0.45）：n=20 → 0.38；n=30 → 0.50；n=50 → 0.68；**n=70 → 0.80**；n=100 → 0.91。

### 3.4 为什么「加样本数」救不了——方差分解（关键）

`【已实测】` 同配置两次独立运行给出 **30% 与 71%**（效果验证报告 §5.2）。
按两个独立二项样本看，这个差距的 z = 2.84，**双侧 p = 0.0045** ⇒
**这个差距本身就不像抽样噪声。**

`【我的推断】` 于是存在一个**运行级随机效应** `τ`（或两次运行的配置其实不同——
现有产物不记录运行身份，两种情况无法区分，见 §4.2 C-1）：

```
Var(p̂) = p(1−p)/n  +  τ²/R
          ↑二项噪声      ↑运行级漂移，靠独立运行轮数 R 摊薄
```

`n` 压二项项，`R` 压运行级项。**加 n 压不掉 τ。**

`【我的建议】` 因此实验设计必须是：

> **两臂在同一轮运行内交错执行**（A、B、A、B…同一批提示词逐条交替），
> 这样轮级项 `τ` 在**差分**里相消；差分方差回到 `2·p̄(1−p̄)/n`，
> 此时 n=70/臂/轮 就能达到 power 0.80（Δ=20 点，disc=0.45）。
> 再叠加 R=3 轮独立运行用于绝对率估计。

`【我的推断】` **「交错」这个设计不能只靠假设**——必须先用一个**双跑对照**验证它：
同一批提示词在**同一轮**内 A/B 交错各跑一次，比较「交错差分」与「跨轮差分」的方差，
确认轮级项确实相消。这是一次 140 次调用的实验，成本约 $0.30 / 40 分钟。

### 3.5 完整设计（可执行）

| 项 | 取值 | 依据 |
|---|---|---|
| 提示词数 n | **70/臂** | McNemar，Δ=20 点，disc=0.45，power 0.80 |
| 每条点击数 | 3 | 与现有基线可比；跨点击翻转率的分母是提示词条数 |
| 独立运行轮数 R | **3** | 摊薄运行级 τ；同时给出 τ 的估计 |
| 执行顺序 | **同轮交错 A/B** | 使 τ 在差分中相消（§3.4） |
| 主指标 | 跨点击翻转率 | §3.1 |
| 分析方法 | 配对 McNemar（不一致对）+ 绝对率的 Wilson 区间 | §3.3 |
| 预注册 | 指标/样本数/排除规则/停止条件，**运行前**写入 `docs/` | §3.7 |
| 成本 | 70×2×3×3 = 1260 次调用 ≈ $2.7 / 约 6 小时 | 按规格 §7 成本表换算 |

`【我的建议】` 成本可大幅压缩：**先做 n=20 的**双跑交错**对照**（§3.4 末段，140 次调用，$0.30），
它同时给出 `e`（§1.2）、`disc`（§3.3）、`τ`（§3.4）三个必需参数。
**用这 140 次调用反推正式实验的 n 和 R，再决定是否投 1260 次。**
这是当前唯一能把「该花多少钱」从猜测变成计算的路径。

### 3.6 门槛重设（可判定性分析）

`【已实测】` 噪声地板 = 41 个百分点。逐条核对规格 §7：

| 门槛 | 现状 | 目标 | 间距 | 判定 |
|---|---|---|---|---|
| 1 clear 翻转率 | 55% | ≤30% | 25 点 | **不可判定**（间距 < 噪声地板） |
| 2 medium 翻转率 | 33% | ≤30% | 3 点 | **不可判定** |
| 3 clear light 出现率（红线） | 52% | ≥42% | 10 点 | **不可判定** |

`【已实测】` 更糟的是：**门槛 1 的目标值 ≤30% 恰好等于「两次同配置运行中较好的一次」**。
把发布门槛定在最好那次上，等于让门槛在重跑时**约等于掷硬币**。
而无偏估计应是 (30%+71%)/2 = **50.5%**。

`【我的建议】` 门槛改法（三条同时做）：

1. **门槛 1 的目标值重设为「≤ 噪声地板内不可判定，先建基线」**，
   即在 §3.5 的设计下重建基线，**不要**沿用 30% 这个数。
2. **每个门槛都同时报「应有多少 / 实有多少」**，分母流失直接判 FAIL（§4.2 A-2/A-4）。
3. **所有门禁指标必须带区间**，单点值不构成判定。规格 §5.3 的「双指标联立」方向是对的，
   但还差一步：**双指标 + 区间 + 预注册**。
