## 〇、一句话结论

**v0.4.0 不是一次「加了功能」的迭代，而是一次「把失败显示成成功」的系统性清理。**

起点是架构审查官判定的一个 **FAIL**：41 条「缺数据被当成没问题」的同族缺陷，其中 13 条是发布阻断级；v0.3.5 已发布版对**新装用户完全不可用**（API Key 存不进去，界面却显示「配置已保存」）。

本轮结束时：41 条清单**全部 P0 闭环**、三套回归全绿且用例数只增不减、**三份被证伪的文档结论已撤回并更正**、以及一条更重要的结论——

> **原规格 §7 作为主线的三条「档位稳定性」门槛，经可判定性推导全部落在不可判定区，已正式作废。**
> v0.4.0 的验收因此改为两条线：**诚实性闭环**（发布阻断级）+ **澄清质量**（唯一可判定的效果抓手）。

## 一、这一轮真正的问题是什么

不是「功能不够」，是**「错了但界面说成功了」**。

| 缺陷族 | 典型 | 后果 |
|---|---|---|
| 缺数据被当成「没问题」 | 配置读失败 → 静默回落默认配置 → 下次保存覆盖原值 | 用户丢失自己的配置，且不知情 |
| 降级被呈现为成功 | 结构解析彻底失败 → 构造 fallback → 界面显示「增强器判断无需修改」 | **断言了一个从未发生的判断** |
| 导入包可以改写本机决策 | 导入包改写 `base_url` → 真实 API Key 作为 Bearer 头发往攻击者地址 | **凭据泄露**（v0.3.5 只防住「Key 的值」，没防住「Key 的目的地」） |
| 产物不编码自身身份 | 评测产物名写死、`--resume` 不校验参数 | **没有人能复核任何一个数字** |
| 指标被另一个指标顶替 | novelty 缺失时用 relevance 顶替，而 composite 是模型排名的排序键 | **排名被一个不存在的维度污染** |

最后两族是这一轮最深的发现——它们不是产品 bug，是**测量系统自己的 bug**。在这套测量系统上做四轮实验、得出三个「已被证伪」的结论，是必然的。

## 二、已闭环的发布阻断项（P0）

## 三、被证伪并已撤回的结论（本轮最诚实的一部分）

**这三处不是「写得不够严谨」，是结论本身就比证据强。全部已更正，原始记录保留。**

### 3.1 人工盲评的「0 胜 27 负 21 平」——是一个大小写反转 bug 的产物

`evaluation/v032_blind_review.py` 把人工胜者 `.lower()` 转小写，却与**大写**的 `enhanced_label` 直接比较。`"a" == "A"` 恒为 `False` ⇒ **任何一条人工非平局判断都必然落进「原文更优」分支**，包括人工真正判增强组胜的那些。实测产物中 `enhanced` 出现 **0/48** 次，而人工原始作答分布是 A:20 / 平:21 / B:7。

| | 原 | 修正后 |
|---|---|---|
| 人工盲评分布 | 0 / 27 / 21 | **10 / 17 / 21** |
| 非平局胜者一致率 | 26.9% | **53.8%** |
| 方向一致性判定 | 不一致 | **一致（弱）**，κ 0.079 → 0.152 |
| clear 档人工胜率 | 0% | **25%**，bootstrap 95% CI [6.2%, 50.0%] |

**影响范围严格划界**：只影响「谁胜」的分类。§5.2 的人工四维 Delta（用大写标签、不依赖 winner）、自动裁判列、21 个人工平局——**均不受影响**。

回归测试 `evaluation/test_v032_blind_review.py`（14 例），**对修复前的代码会失败 6 例**（已实测验证）。

### 3.2 「温度 0.35→0.1 约 2.5 个标准误」——实际 1.65 SE，落在噪声地板以内

| 主张 | 复核结论 |
|---|---|
| 55% → 30% | 同一配置跑两次给出 **30% 与 71%**，报告取的是**较好的一次**；无偏估计是 **50.5%** |
| 「约 2.5 个标准误」 | 实际 **1.65 SE**，双侧 p ≈ 0.10，**不显著** |
| 效应量 25 点 | **小于**同配置两次运行的差 41 点（噪声地板）⇒ 不可解读 |

⇒ 温度改动**保留**（无实测害处、方向可解释），但**不再声称量化收益**。`provider.rs` 的注释已改为直陈「效应落在噪声地板之内，方向未确认」。

### 3.3 「自动裁判与人工完全反向」——撤回

原论证用「人工 clear 档 0 胜 / 8 平 / 8 负的分布形状」当决定性证据。修正后在**同一批 16 个 clear 盲评单元**上：自动裁判 8 胜 / 5 平 / 3 负，人工 4 胜 / 8 平 / 4 负——**两者同向、量级接近**，不再构成「反向」证据。

连带影响：v0.3.2 报告 §八第 1 条的「LLM-judge 长度/结构偏好导致方向相反」假说**失去本轮数据支持**（未被证伪，但需配对实验才能坐实）。

**《效果验证报告》§2.1 的结论（「来源是改多了，不是改错了」）不变，但支撑它的证据换过一轮**：改用三条**不受缺陷影响**的证据——人工四维 Delta 的损伤排序（准确性 −0.33 最小、清晰度 −0.54 最大 ⇒ 是变绕不是变错）、膨胀比 ×4.63、自动裁判 clear 档变差率 41.1%。

## 四、验收标准被改写：三条主线条正式作废

这是本轮对「方向」影响最大的一件事。

原规格 §7 的三条稳定性门槛，经 `evaluation/gate_decidability.py` 的可判定性推导（`Var = p(1-p)/n + τ²/R`，τ = 41 点噪声地板）：

| 门槛 | 间距 | 判定所需 n | 判定所需 R | 状态 |
|---|---|---|---|---|
| clear 翻转率 55% → ≤30% | 25 点 | 24（R=50 时 n=347） | **50 轮** | **void（不可判定）** |
| medium 翻转率 33% → ≤30% | 3 点 | 1493（R=3000 时 n=85013） | **3000 轮** | **void（不可判定）** |
| clear light 出现率 52% → ≥42% | 10 点 | 154（R=500 时 n=792） | **500 轮** | **void（不可判定）** |

要让第一条变成可判定的，需要 347 条样本 × 50 轮 ≈ **17,350 次调用（约 $38、数小时）**，而且结论几乎必然是「仍不稳定」——效果验证官已判定 **none/light 边界不是客观可判的划分**（"这条信息缺了，目标模型是给不出东西，还是给得出但不够好？后者不是客观事实"）。

**⇒ 三条作废。但作废 ≠ 通过**：它们仍显式出现在门禁输出里，只是不参与放行判定。

**⇒ v0.4.0 的验收改为两条线**（2026-10-20 用户决断）：

- **线一 · 诚实性闭环（发布阻断级，全部必须闭环）**
  1. 失败伪装清单**全部 P0** 转 FIXED，且无 P0/P1 处于 UNVERIFIED；
  2. `python scripts/check-fail-open.py` 退出码 0；
  3. `npm test` / `pytest evaluation -q` / `cargo test` 全绿，**用例数只增不减**。
- **线二 · 澄清质量（唯一可判定的效果抓手）**
  4. 门槛 4（翻译场景人工盲评命中率 11% → ≥60%）、门槛 5（severe 整体命中率 73.3% → ≥85%）、门槛 6（严重档「问已知信息」2/20 → 0）——可判定性推导为 **active**；
  5. 门槛 7（交付状态漂移 = 0）、门槛 8（既有测试不回退）。

**档位稳定性明确推迟**，留给「把档位决策从 LLM 手里拿走」（规则化 / 前置分类器 / 让用户在两个结果里选）有新方案之后再测。在那之前**不对外宣称任何稳定性数字，也不设任何稳定性门槛**。

### 5.2 可执行的门禁

- `scripts/check-fail-open.py` + `docs/v040-失败伪装清单.json`（41 条，机器可读，含 `claim` / `mechanism` / `consequence` / `acceptance` / `probe`）。
- 纪律：**探测不到 ≠ 通过**。探针坏掉或代码块定位不到一律报 `UNVERIFIED`，绝不报 `FIXED`。
- 新增 `required_regex` **反向探针**：用于「压根没做某个检查」这类缺陷（没有「坏字符串」可找）。语义为「找到必需逻辑 ⇒ FIXED，找不到 ⇒ OPEN」；文件不存在或正则写坏 ⇒ `UNVERIFIED`。自测 4 例全对。
- `evaluation/check_gate_behavior.py`：**子串探针看不见行为漂移时的兜底**，用 5 个由真实聚合产出的 fixture 逐条判定。

### 5.3 口径变更单独记账

`docs/v040-口径变更记录.md`：A 家族改了 `report.py` 的聚合口径（缺数据不再写成 0、裁判失败不再静默出分母等），**历史报告的数字不改**——回填新口径的数字等于用另一套判据伪造历史，那正是本项目在修的那类缺陷。要拿新口径下的数字，只有一条路：**重跑**。

记录里写明了方向性变化：**「胜率会更难看：裁判失败越多，胜率越低。这是修正，不是退化。」**

## 十、阶段小结

### 9.1 经验教训

**① 结论比证据强，是这个项目最贵的失败模式。**
本轮撤回的三处结论（盲评 0 胜、2.5 个标准误、自动裁判与人工反向）**没有一处是数据错了**，而是**代码把数据读错了**。其中盲评那处是一个大小写反转——`"a" == "A"` 恒为 False，27 条人工判断被全部记成"原文更优"。在这样的测量系统上做四轮实验、得出三个"已被证伪"的结论，是必然的。
⇒ **下阶段要避免的同类问题：任何一个数字进报告之前，先问「这个数字在代码里是怎么算出来的」。** 不是问「它看起来合理吗」。

**② 失败伪装的关键不是"有没有失败"，而是"失败之后界面说什么"。**
本轮 41 条缺陷里，最有价值的不是那个凭据泄露（P0-2），而是这一类：`enhancement_level` 在降级路径上被硬编码成 `none`，于是界面斩钉截铁地说「增强器判断无需修改」——**断言了一个从未发生的判断**。用户看不出哪里错了，只觉得"这工具不太行"。
⇒ **下阶段要避免的同类问题：任何"成功/失败"的结论性文案，都必须能追到一个真实的判断来源。** 追不到就显示"不可判定"。

**③ 验收物比 deadline 可靠。**
本轮唯一一次真正决定方向的动作，是 `check-fail-open.py` 退出码从 1 变成 0。反过来，v0.4.0 原规格 §7 的三条主线条目**在验收物面前现出了原形**：它们在任何可行样本量下都不可判定（G1 需 17,350 次调用约 $38），于是被作废。
⇒ **下阶段要避免的同类问题：定门槛之前先算"可判定性"，再定门槛值。** 门槛间距小于噪声地板的门槛不是"严"，是"不可判定"——它只会让人反复重跑直到掷骰子出好结果。

**④ 工具本身也会说谎。**
本轮修了检查器两个真问题：① 探针命中的是**注释**而不是代码（A11 明明修好了却报 OPEN）；② 子串探针看不见"加了身份闸"这类行为级修复（D2 修了仍报 OPEN）。同时"探针查不到"和"探针坏掉"必须分开——`kind=manual` 一律 UNVERIFIED，绝不报 FIXED。
⇒ **下阶段要避免的同类问题：验收器要接受"自己会被骗"这件事。** 门禁是必要条件不是充分条件，每条修复还得配行为级回归测试。

**⑤ 团队会被基础设施打断，交付物会留在半路。**
本轮两个实现 bot 的会话都被运行时崩溃中断（"interrupted because the previous local runtime stopped"），留下大量未提交的合格改动。Chief 接管审阅、跑负向对照、补齐测试后才提交。**如果当时直接丢弃，这批工作就白做了。**
⇒ **下阶段要避免的同类问题：工作区里未提交的改动是资产不是垃圾。** 先审后接，不要 `git checkout --`。

**⑥ 重建不是找回。**
F 盘丢失的 5 个测量脚本是**重建**的，不是找回的。重建的脚本能复算出报告原表的数字（clear 20/11/55%、medium 18/6/33%），但**不等于原脚本被找回来了**——这一点在证据目录里写明了。
⇒ **下阶段要避免的同类问题：声称"恢复"之前，先分清"找回原件"和"按口径重建"。** 两者对可复核性的意义完全不同。
